# Известные ограничения MVP (на 23.09.2026, 15:20)

Сознательные упрощения за 5 часов. Не влияют на обязательный сценарий ТЗ §2 и §11.

| Ограничение | Почему оставили | Что бы сделали дальше |
|---|---|---|
| Нет владельца задачи: любой посетитель в режиме «Я бизнес» может редактировать чужую карточку, выбирать или отклонять отклики | ТЗ §7 не требует ролевой модели; демо идёт от одного лица | Токен владельца, выдаваемый при создании задачи, и проверка его на изменяющих действиях |
| Правка опубликованной карточки снимает её с каталога до повторного подтверждения | Баллы только за подтверждённые поля (ТЗ §4); версия-снимок не хранится | Хранить последнюю подтверждённую версию и показывать её в каталоге, пока новая не подтверждена |
| Формула рейтинга — ключевые слова и regex, не понимание смысла | Прозрачность и детерминизм важнее (ТЗ §4: «расшифровка начисленных баллов»); список правил открыт | Расширять признаки по реальным карточкам; длинная бессмыслица в «контексте» пока получает полный балл |
| Guard не ловит смену смысла отрицанием словами из исходника | Любая семантическая проверка — снова LLM, которой нельзя доверять факты | Второй проход модели «сверь карточку с исходником» с человеческим подтверждением, как сейчас |
| Рекомендации командам — пересечение слов, без учёта смысла; в UI показываются как дополнение | ТЗ: рекомендации не ограничивают каталог; векторная база не нужна (§7) | Эмбеддинги по навыкам и отраслям |
| Баллы команде за этап начисляются одной кнопкой «Подтвердить этап» (+10) | ТЗ §7: полный трекер не требуется, достаточно отклика и решения | Этапы с датами и подтверждением обеих сторон |
| Вход команд по одноразовому коду в демо-режиме: код всегда `000000`, реальная отправка email/SMS не реализована, сессии в памяти сервера (перезапуск разлогинивает) | ТЗ §7 не требует регистрации; для демо и экспертов нужен предсказуемый вход без внешних сервисов (Положение п. 5.6.6) | Отправка кода через email/SMS-провайдер, таблица сессий |
| Нет регистрации бизнеса, уведомлений, файлов, мобильной вёрстки | ТЗ §7 явно исключает | — |
| Команда из двух участников при «3–5» в ТЗ | Положение хакатона п. 1.4 допускает 1–3; вопрос организаторам задан | — |
| Нет роли куратора/эскроу: деньги и гранты вне MVP | В кейсе нет платежей; защита от обмана — принятие с двух сторон и баллы только за подтверждённый этап | Роль куратора AI Sana: холд средств и выпуск после подтверждения этапа обеими сторонами |
| Гонки при одновременных действиях: установка контакта задачи и accept/decline против одновременного решения бизнеса — «последний побеждает» | Один пользователь на роль в демо | Транзакции с проверкой статуса |
