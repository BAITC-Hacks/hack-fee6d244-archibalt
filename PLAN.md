## 3. Сквозной сценарий (ТЗ §2) → экраны

1. `/` — каталог: карточки, сортировка по рейтингу, фильтры «отрасль» и «уровень готовности», бейдж уровня. Кнопка «Новая задача».
2. `/task/new` — черновик: одно текстовое поле + отрасль.
3. `/task/{id}/clarify` — AI вернул ≥3 вопроса, бизнес отвечает. Кнопка «Собрать карточку».
4. `/task/{id}/edit` — редактируемая карточка (10 полей ТЗ §3), справа рейтинг: балл, расшифровка по 7 показателям, список «что добавить, чтобы +N». Пересчёт при сохранении. Кнопка «Подтвердить и опубликовать».
5. `/task/{id}` — публичная карточка + отклики. Команда: форма «идея, план, срок, ссылка». Бизнес: «Выбрать» / «Отклонить» по каждому отклику, «Подтвердить этап» → команде начисляются баллы.
6. `/teams` — профили команд и «Рекомендуемые задачи» по пересечению навыков/интересов с тегами задачи.

## 4. Формула рейтинга (прозрачная, детерминированная, в коде, не в AI)

Веса из ТЗ §4: контекст и потребность 20, данные 20, результат 15, критерии успеха 15, ограничения 10, пользователи 10, связь с бизнесом 10.

Каждое поле оценивается правилом в `internal/rating`: пусто → 0; заполнено, но коротко или без ключевого признака → 50% веса; полно → 100%. Признак «полно» задаётся явно на поле (пример: критерии успеха содержат число или измеримый признак; связь с бизнесом содержит контакт и формат). Балл считается только по **подтверждённым** полям (после «Подтвердить»). Расшифровка и список недостающего генерируются той же функцией. Уровни 0–39/40–69/70–89/90–100 по ТЗ. Формула дословно попадает в README.

AI на рейтинг **не влияет** напрямую: он предлагает вопросы и черновик карточки, человек редактирует и подтверждает.

## 5. AI-функция (ТЗ §5, 10 баллов рубрики)

Два вызова, оба structured output:
- `questions(draft) → {questions: [≥3], missing_fields: [...]}` — вопросы только по отсутствующим полям.
- `card(draft, answers) → {поля карточки; каждое поле либо текст, взятый из слов пользователя, либо null}`.

Защита от выдумок: системный промпт «только из текста пользователя, иначе null»; после ответа проверка, что каждое непустое поле имеет пересечение слов с исходным текстом+ответами, иначе поле обнуляется и помечается «не подтверждено». Невалидный JSON или ошибка API → повтор один раз → mock-режим с тем же форматом. Промпт, схемы и пример входа/выхода лежат в `ai/README.md`.
