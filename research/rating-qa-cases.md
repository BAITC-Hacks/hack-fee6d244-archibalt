# Проверка семантики рейтинга: пять синтетических карточек

Источник: независимый QA-прогон через JSON API на `55d384b`, 23.09.2026. Данные вымышлены. Ожидаемые баллы B–E — экспертная оценка полезности поля, а не дословное требование ТЗ; владелец формулы должен проверить её и закрепить выбранное правило тестами.

## Как воспроизвести

1. Создать задачу через `POST /api/tasks` с `{"draft_text":"Заявки теряются в Excel, нужна очередь со статусами.","industry":"Сервис"}`.
2. Передать поля из базовой карточки через `PUT /api/tasks/{id}/fields`, для B–E заменив только поле из таблицы ниже.
3. Подтвердить через `POST /api/tasks/{id}/confirm` и сравнить `score` и `breakdown[].earned` в порядке `context_need, data, expected_result, success_criteria, constraints, users, business_link`.

Базовые поля A:

```json
{
  "title": "Очередь заявок ремонтной мастерской",
  "context": "В учебной ремонтной мастерской заявки приходят по почте и в Excel, оператор переносит их вручную и теряет текущий статус.",
  "need": "Нужно собрать все заявки в одну очередь и показывать оператору текущий статус и следующий шаг по каждому заказу.",
  "users": "Операторы и мастера учебной ремонтной мастерской, которые обрабатывают заявки клиентов.",
  "data": "Подготовлена таблица Excel со 100 синтетическими заявками; дадим доступ к CSV в первую неделю пилота.",
  "constraints": "Пилот за четыре недели, только синтетические заявки из CSV, без персональных данных и внешних интеграций.",
  "expected_result": "Нужен прототип экрана очереди заявок с фильтром по статусу и карточкой каждого заказа.",
  "success_criteria": "В 9 из 10 тестовых сценариев оператор находит заявку и меняет статус менее чем за 2 минуты.",
  "contact": "demo@example.invalid",
  "interaction_format": "Еженедельный созвон и обратная связь по тестовым сценариям в течение дня."
}
```
