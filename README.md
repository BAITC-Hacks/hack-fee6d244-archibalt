# Archibalt — AI Sana Challenge Hub: от бизнес-задачи к студенческой команде

MVP для кейса «Рейтинг качества бизнес-задач и открытый выбор команд» (HackAlem AI, трек Education, задание 01, ТЗ в [`TASK.md`](TASK.md)).

Представитель бизнеса пишет слабое описание задачи. AI задаёт минимум три уточняющих вопроса по недостающим сведениям, собирает из ответов редактируемую карточку из 10 полей и **ничего не выдумывает**. Система считает прозрачный **рейтинг готовности 0–100**, показывает, за что начислены баллы и что дописать. После ручного подтверждения карточка публикуется в открытом каталоге на позиции по рейтингу. Любая студенческая команда откликается идеей, планом, сроком и ссылкой. Бизнес вручную выбирает одну, несколько или ни одной команды.

Команда: Абылай (архитектура, бэкенд, AI, рейтинг), Ильяс (продукт, фронтенд, данные, демо). Разработка велась с AI-агентами (Claude Code, Codex), см. `AGENT_HANDOFF.md`.

## Быстрый запуск (для проверки экспертами)

Нужен только Docker (Docker Desktop 4.x или docker + compose v2). Личные аккаунты и ключи **не нужны**: без `OPENAI_API_KEY` AI работает в локальном mock-режиме с тем же форматом входа и выхода.

```bash
git clone https://github.com/BAITC-Hacks/hack-fee6d244-archibalt.git
cd hack-fee6d244-archibalt
docker compose up --build
```

Откройте <http://localhost:8080>. Нужны свободные порты 8080 (приложение) и 5432 (Postgres, слушает только 127.0.0.1). Проверка, что всё живо: <http://localhost:8080/api/health> → `{"ok":true,"db":true,"ai_mode":"mock"}`.

Живой AI через OpenAI (по желанию): создайте `.env` из `.env.example`, впишите `OPENAI_API_KEY`, перезапустите `docker compose up --build`. `ai_mode` станет `openai`. При ошибке API система один раз повторяет запрос и откатывается на mock, не роняя сценарий.

Сбросить данные и заново загрузить демо-набор: `docker compose down -v && docker compose up --build`.

### Запуск без Docker (разработка)

Требуется Go 1.25+, Node 22+, PostgreSQL 16 (или `make db`, который поднимает только БД в Docker).

```bash
make db                          # postgres на localhost:5432, пароль hack
make run                         # Go API на :8080, seed загружается при пустой БД
cd web && npm ci && npm run dev  # фронт на :5173 с proxy /api → :8080
```

Тесты: `make test` (Go, без БД) и `TEST_DATABASE_URL=postgres://postgres:hack@localhost:5432/hack?sslmode=disable go test ./internal/store/` (с БД).

## Формула рейтинга готовности (ТЗ §4)

Рейтинг измеряет **готовность конкретной задачи к работе со студентами**, а не известность компании. Считается детерминированно в коде (`internal/rating`), AI на балл не влияет.

Семь показателей с весами из ТЗ, сумма 100:

| Показатель | Вес | Поля карточки | Полный балл, если |
|---|---|---|---|
| Контекст и потребность | 20 | context, need | оба поля содержательно описаны: что происходит сейчас и что нужно изменить |
| Данные и материалы | 20 | data | назван материал (выгрузка, таблица, CRM, API, примеры, интервью) **и** способ или срок передачи |
| Ожидаемый результат | 15 | expected_result | назван конкретный артефакт (прототип, отчёт, сервис, дашборд, модель) с функцией |
| Критерии успеха | 15 | success_criteria | есть число с метрикой или единицей, либо описан способ проверки |
| Ограничения | 10 | constraints | указаны сроки, технологии, доступы или иные границы |
| Пользователи | 10 | users | названа роль или группа, для кого решение |
| Связь с бизнесом | 10 | contact, interaction_format | пригодный контакт (email, Telegram, телефон) **и** канал с ритмом встреч или сроком ответа |

Начисление на показатель: **0** — пусто, заглушка (`x`, `-`, `todo`, «не знаю», в том числе внутри текста), текст без признаков короче трёх значимых слов, отказ без плана («данных не будет», «встреч не будет») или телефон из одинаковых цифр; **половина веса** (округление вниз) — заполнено, но признак полноты не найден (например, «передадим позже» без срока и способа); **полный вес** — условие из таблицы выполнено, причина называет найденный признак. У составных показателей половина, если закрыто одно поле из двух. Длина текста — вспомогательный сигнал, повтор фраз и пробелы балл не поднимают.

Известное ограничение: признаки — ключевые слова и регулярные выражения, а не понимание смысла. Осмысленный текст простыми словами без ключевых признаков получит половину веса, а длинная бессмыслица в полях «контекст» и «потребность» — полный. Список правил открыт в `internal/rating/rating.go` и на странице «Как работает AI».

`score = Σ earned`. Уровни: **0–39 черновик** (виден в каталоге с пометкой), **40–69 рабочая** (можно откликаться и рекомендовать), **70–89 готовая** (повышенная позиция), **90–100 приоритетная** (выделена). Низкий рейтинг задачу не скрывает и отклик не запрещает.

`breakdown` объясняет каждый показатель словами, `missing` перечисляет, что дописать и сколько это даст (`gain = weight − earned`), отсортировано по выгоде. Рейтинг пересчитывается при каждом сохранении.

**Предварительный и официальный балл.** До ручного подтверждения балл предварительный, задачи нет в каталоге. Подтверждение публикует карточку с официальным баллом. Правка опубликованной карточки снимает её с каталога до повторного подтверждения (известное упрощение MVP: версия-снимок не хранится).

## Правила каталога

- В каталоге только подтверждённые задачи. Все видны всем командам, ограничений на просмотр нет.
- Сортировка: `score` по убыванию, при равенстве раньше опубликованная выше.
- Фильтры: отрасль (`industry`) и уровень готовности (`level`).
- Отклики не лимитируются: любая команда может откликнуться на любую задачу, включая черновики.
- Автоназначения нет: только ручные `select` / `reject` по каждому отклику; можно выбрать 0, 1 или несколько команд.
- Решения по откликам (`select` / `reject` / `hold` / `confirm-stage`) у задачи с контактом заявителя принимает только он, войдя по этому контакту; у задач без контакта (демо-набор) решения открыты. Дополнять карточку может любой.
- Рекомендации (`GET /api/teams/:id/recommended`) — дополнение: пересечение навыков и интересов команды со словами карточки, только задачи от уровня «рабочая»; общий каталог они не ограничивают.

## AI-функция (ТЗ §5)

Два вызова OpenAI Responses API со строгой JSON-схемой (`strict: true`), без SDK, промпты и схемы в [`internal/ai/prompts.go`](internal/ai/prompts.go) и на странице `/api/ai`:

1. **Вопросы**: по черновику определить незакрытые поля и задать 3–5 вопросов, каждый строго про одно поле.
2. **Карточка**: собрать 10 полей **только** из черновика и ответов; для отсутствующих сведений вернуть пустую строку.

Защита от выдуманных фактов (`internal/ai/guard.go`, работает и для OpenAI, и для mock): каждое непустое поле, включая название, проверяется на пересечение слов с исходным текстом пользователя, а любое число должно встречаться в исходнике рядом с тем же словом («2 недели» нельзя превратить в «2 оператора»); иначе поле очищается. Последний реальный вызов с сырым ответом модели и списком вырезанных полей виден в `GET /api/ai` → `last_call`. Ограничение: смена смысла через отрицание словами из исходника не ловится, поэтому карточку подтверждает человек. Человек редактирует и подтверждает карточку до публикации.

Обработка ошибок: таймаут 10 с на вызов, при ошибке сети, статуса или невалидного JSON один повтор (не более 20 с на вызов), затем локальный mock с тем же форматом; текст последней ошибки виден в `GET /api/ai` → `last_error`. Mock детерминирован: вопросы по таблице ключевых слов и приоритету весов, карточка из ответов.

AI **не** выставляет баллы, **не** выбирает команды и **не** публикует задачи. Персональные признаки участников не используются.

## Тестовые сценарии

Автотесты: `go test ./...` — формула (контрпримеры на заглушки), AI (mock, Guard, откат при 500), хендлеры (сквозной путь и ошибки 400/404), хранилище (миграция, seed, FK, баллы за этап).

Ручная проверка основного сценария (5 минут, всё в интерфейсе):

1. Каталог: видны 5 демо-задач с уровнями от «черновик» до «готовая», сортировка по баллу, фильтры работают.
2. «Новая задача» → ввести слабый черновик, например: *«Нужно приложение для учёта заявок, сейчас всё в Excel и теряется»*, отрасль «Сервис».
3. Появляются ≥3 вопроса про недостающие поля (данные, критерии, контакт…). Ответить.
4. Карточка собрана из ответов, незаполненные поля пустые (AI ничего не добавил). Балл «предварительно», разбивка по 7 показателям, список «что дописать».
5. Дописать критерии успеха с числом («снизить время обработки на 30%») и контакт с email и ритмом созвонов → сохранить → балл вырос, уровень изменился.
6. «Подтвердить и опубликовать» → задача в каталоге на позиции по баллу.
7. Переключиться в режим «Я команда» → открыть задачу → отправить отклик (идея, план, срок, ссылка). Второй отклик от другой команды тоже проходит.
   Вход команды: «Я команда» → email или телефон → код `000000` (демо-режим, код не отправляется, подсказка на экране) → отклик; страница «Мои отклики» показывает отправленные отклики и их статус.
8. Режим «Я бизнес» → выбрать один отклик, отклонить другой. Можно выбрать несколько или отклонить все.
   Вход бизнеса: укажите email/телефон при создании задачи (или на подтверждении), затем «Я бизнес» → вход тем же кодом `000000` → «Мои задачи»: отклики, принять/отклонить. Задачи без контакта открыты для решений (демо).
   Команда подтверждает проект у выбранного отклика («Принять» / «Отказаться»); под откликом — чат команды и заявителя (обновляется по WebSocket).
9. (Дополнительно) «Подтвердить этап» у отклика, принятого командой → команде начислены баллы.

Проверка ошибок: пустой черновик → сообщение, отклик без ссылки → сообщение, `/api/tasks/999` → 404.

Тот же сценарий через curl — в [`API_CONTRACT.md`](API_CONTRACT.md); демо-набор (5 черновиков, 5 карточек, 5 команд, 5 откликов) — в [`seed/`](seed/).

## Дальнейшее развитие

- **Куратор AI Sana как эскроу.** Третья роль (модератор платформы) держит грант или оплату на холде и выпускает после того, как обе стороны подтвердили этап. Механика статусов `selected → accepted → этап подтверждён` уже в API, статус `on_hold` заложен; остаётся роль куратора и интеграция с платёжным или грантовым контуром.
- Реальная отправка одноразовых кодов на email/SMS вместо демо-кода `000000`.
- Версия-снимок опубликованной карточки при правке, чтобы задача не пропадала из каталога.
- Рекомендации командам по смыслу, а не по пересечению слов.
