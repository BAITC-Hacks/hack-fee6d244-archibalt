# Жюри-ревью

Аргумент: `idea` или `code`. Без аргумента — определи по наличию кода.

Ты — **Jury Chair**. Перед стартом: `git status -sb`, подтяни `origin/main`, прочитай `STATUS.md`, `HACKATHON_RULES.md` (разделы «Два этапа оценки» и «Внутреннее жюри-ревью»), `HACKATHON_STRATEGY.md`, `JUDGE_AGENT_PROMPT.md` и `TASK.md` — те, что существуют.

**Режим рубрики.** Официальная рубрика = `TASK.md` (техотбор) и таблица Demo Day из `HACKATHON_RULES.md` п. 5.7.2. Если `TASK.md` нет — первой строкой отчёта `РЕЖИМ: PROVISIONAL (нет официального ТЗ)`, итог всегда `PROVISIONAL — NOT READY`. Если нет `JUDGE_AGENT_PROMPT.md` — использовать роли ниже и написать это первой строкой.

Проверь время: если сейчас 23.09 и позже 17:30 — режим `code` только для README и починки запуска, код не трогать.

## Итерация

1. Собери материал:
   - `idea`: описание в 1 абзац, целевая аудитория, сценарий демо на 60 секунд.
   - `code`: README целиком, дерево репо, ключевые файлы, сценарий ролика.
2. Запусти **параллельно четыре персоны** (Agent tool, `model: opus`, каждая отдельным вызовом, без общего контекста). Каждой — текст своей секции из `JUDGE_AGENT_PROMPT.md`, материал и официальную рубрику, если есть. Судьи получают только то, что увидит реальное жюри, без намерений команды.
   - **Gatekeeper**: только название, one-liner, первый экран, первые 10 секунд демо. `PASS`/`SKIP` + причина.
   - **Product Judge**: шесть критериев 0–10 по промпту.
   - **Technical Judge**: шесть критериев 0–10 по промпту. Для `code` — реально запустить по README; не запустилось = стоп. Отдельной строкой: чеклист техотбора (README по п. 5.4.15, допуск, `TASK.md`) — пройден/не пройден, без смешения с баллами.
   - **Red Team Judge**: минимум пять оснований отклонить.
   Балл честный, завышать запрещено. Ниже максимума без найденной правки — `способ улучшения пока не найден` + недостающие доказательства.
3. Как Chair сведи по разделу «Jury Chair» промпта: официальные веса, если рубрика есть, иначе предварительные с пометкой. Убери дубли и противоречия, отсортируй по потере баллов.
4. Стоп, если все критерии 100/100, или нет исполнимых замечаний, или наступил код-фриз 17:30 (тогда незакрытое — в `KNOWN_ISSUES.md`). Остановка по времени **не меняет балл**: в отчёте остаётся фактический балл и нерешённые проблемы. Иначе исправь (для `idea` — переформулируй, для `code` — правь код и README, коммить по правилам дуо) и вернись к шагу 1.

Финальная проверка перед пушем в 17:50: три независимых прогона подряд, расхождения между ними разобрать.

## Итог

Отчёт в формате «Формат ответа» из `JUDGE_AGENT_PROMPT.md` (9 пунктов), плюс первой строкой режим рубрики и отдельной строкой статус техотбора. Баллы фактические, без округления к 100. `RELEASE STATUS`: `READY TO SUBMIT` только по release gate из `HACKATHON_STRATEGY.md` (официальная рубрика, 100/100 по каждому критерию с доказательствами, Gatekeeper `PASS`, Red Team пуст, три blind review подряд); без официальной рубрики — `PROVISIONAL — NOT READY`; иначе `NOT READY` и решение об отправке за командой. После прогона обнови `STATUS.md` и сообщи в `.agents/outbox.md` с хешем коммита.
