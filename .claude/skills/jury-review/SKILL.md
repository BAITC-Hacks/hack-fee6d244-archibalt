# Жюри-ревью

Аргумент: `idea` или `code`. Без аргумента — определи по наличию кода.

Ты — оркестратор. Перед стартом прочитай `HACKATHON_RULES.md` (разделы «Два этапа оценки» и «Внутреннее жюри-ревью»), `HACKATHON_STRATEGY.md`, `JUDGE_AGENT_PROMPT.md` и `TASK.md` — те, что существуют. Промпты жюри бери из `JUDGE_AGENT_PROMPT.md`, если файл есть; иначе — роли ниже.

Проверь время: если сейчас 23.09 и позже 17:30 — режим `code` только для README и починки запуска, код не трогать.

## Итерация

1. Собери материал:
   - `idea`: описание в 1 абзац, целевая аудитория, сценарий демо на 60 секунд.
   - `code`: README целиком, дерево репо, ключевые файлы, сценарий ролика.
2. Запусти **параллельно три агента-жюри** (Agent tool, каждый отдельным вызовом, без общего контекста). Каждому — материал, таблицу критериев Demo Day из `HACKATHON_RULES.md` и одну роль:
   - **Инвестор**: ценность (25), потенциал (20).
   - **Техэксперт**: результат и качество (20), инновационность (15). Для `code` — реально запустить по README; не запустилось = стоп. Отдельной строкой: чеклист техотбора (README по п. 5.4.15, допуск, ТЗ из `TASK.md`) — пройден/не пройден, без смешения с баллами.
   - **Пользователь/зритель**: презентация и ясность (20). Порог 10 секунд для первого экрана/абзаца/кадра, 30 секунд для README и ролика целиком.
   Формат ответа: баллы по своим критериям, до 3 замечаний `[-N баллов] проблема → что сделать`. Ниже 100 без конкретной правки — недопустимо.
3. Сведи: убери дубли и противоречия, отсортируй по потере баллов.
4. Стоп, если все критерии 100/100, или нет исполнимых замечаний, или наступил код-фриз 17:30 (тогда незакрытое — в `KNOWN_ISSUES.md`). Иначе исправь (для `idea` — переформулируй, для `code` — правь код и README, коммить по правилам дуо) и вернись к шагу 1.

Финальная проверка перед пушем в 17:50: три независимых прогона подряд, расхождения между ними разобрать.

## Итог

Короткий отчёт: баллы по итерациям, статус техотбора отдельной строкой, что исправлено, что осталось. Без пересказа замечаний целиком.
